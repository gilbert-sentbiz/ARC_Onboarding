1.  개요


Arc는 현재의 이메일 및 Jira 기반 온보딩을 셀프서비스 포털로 대체한다. 잠재 고객은 아래 순서대로 네 개의 페이지를 거친다.
페이지
	역할
	1. 문의 페이지
	SentBe 홈페이지의 공개 양식이다. 리드 정보를 수집한다. 산출물 → 영업 적격성 판단.
	2. 포털 인테이크  /  세그먼트 분류
	영업팀이 리드를 초대한 뒤, 고객은 매직 링크로 Arc에 로그인한다. 짧은 질문 세트에 답하면 Arc가 해당 고객이 속하는 세그먼트를 판별한다.
	3. 정보 입력
	세그먼트에 따라 고객이 필요한 정보를 입력한다. (고객 정보 양식 필드, 즉 정보 수집)
	4. 문서 업로드
	세그먼트에 따라 고객이 필요한 문서를 업로드한다. (정보 검증)
	

범위 밖: 백오피스 스크리닝, 리스크 평가, 승인 워크플로, NSB / BaoKim 계정 프로비저닝. 이는 마스터 스펙에서 다룬다.


FI 고객 관련 참고: NDA 확인은 Arc 외부에서 포털 진입 전 단계로 처리되며 영업이 주도한다. 포털 매직 링크 초대는 NDA가 확인된 이후에만 발송된다.

Arc에는 여섯 개의 고객 세그먼트가 있다. 하나의 고객은 하나의 엔터티 레벨 세그먼트와 0개 이상의 서비스 레벨 세그먼트에 동시에 해당할 수 있으며, 적용 가능한 모든 요구사항의 합집합이 적용된다.

4.  세그먼트별 요구사항


각 세그먼트별로 (a) 고객이 정보 입력 페이지에서 입력해야 하는 것, (b) 고객이 문서 업로드 페이지에서 제출해야 하는 것을 정의한다. 검증 규칙, KYC 심사자 체크리스트, 스크리닝 로직은 의도적으로 본 문서 범위 밖이며 마스터 스펙을 참고한다.
4.1  SentBiz Corporate
통합 대기 중  ·  정보 필드는 고객확인서(센트비즈 이용계약서 4페이지의 Customer Information Form)에서 가져왔다. 문서 목록은 현재 스펙 §5를 반영한다.
가시성을 위해 원본 문서에서 가져왔다. 아직 마스터 스펙에 병합되지는 않았으며, 정확한 필드 세트, 순서, 필수/선택 여부는 추후 확인이 필요하다.

5.  범위 밖 — 이후 단계에서 계획


이 문서는 온보딩의 고객 대면 영역만 다룬다. 아래의 백오피스 단계는 Arc의 더 넓은 자동화 로드맵에 포함되며 전체 arc-product-spec.md에 명세되어 있다. 다만 영업, 운영, 외부 공유용으로 본 문서를 깔끔한 기준 문서로 유지하기 위해 의도적으로 여기서는 범위 밖으로 둔다.
모듈
	역할
	자동 스크리닝 파이프라인
	제출 후 동기식 5단계 진단 파이프라인 실행:  재신청자 탐지  ·  블랙리스트 스크리닝  ·  완전성 점검  ·  문서 규정 준수 규칙  ·  제재 / PEP 스크리닝(ComplyAdvantage)  ·  리스크 사전 입력. 스크리닝 보고서를 생성하며, 최종 판단은 사람이 한다.
	리스크 평가
	9개 질문으로 구성된 리스크 양식. 이 중 4개는 스크리닝 데이터로 자동 입력되고 5개는 수동 점수화한다. 두 가지 점수화 방식(범주형 Low/Med/High, 정량형 0–10)을 지원하며 세그먼트별로 관리자가 설정 가능하다.
	승인 워크플로
	단계별 라우팅 — LOW는 자동 승인, MEDIUM은 Tier 1(Daisy / Q / Cecille, 상품별), HIGH 또는 FI는 Tier 2(Esther)로 간다. 상품별 리뷰어 팀은 주담당 + 백업 구조를 가진다. 권한 오버라이드 모드와 승인 취소 처리도 정의되어 있다.
	추가 정보 요청 및 재제출
	심사자가 추가 정보가 필요할 경우 Arc가 구조화된 고객 요청을 생성한다. (기한 기반, 자동 타임아웃) 고객은 동일한 제출 페이지로 돌아오며 표시된 문서를 다시 제출한다. 재스크리닝은 실패한 단계부터 이어서 실행된다.
	계정 프로비저닝
	승인 시:  Client ID 즉시 발급.  COAS 고객 — NSB 12개 엔드포인트 프로비저닝 페이로드 자동 생성(상업 승인 필요).  VCMO 고객 — BaoKim VA 추적(현재 수동, API 검토 중).
	운영 분석
	시간 기반, 물량, 리뷰어, 품질 지표를 Executive, Operations, Quality, Compliance 대시보드로 노출한다. 모든 상태 전환은 이벤트로 기록된다.
	관리자 패널
	규칙, 분류체계, 세그먼트, 리뷰어 배정, 임계값, 타임아웃/SLA 값, 이메일 템플릿을 모두 코드 변경 없이 관리자가 수정할 수 있다.
	감사 추적
	도메인 이벤트 로그가 곧 감사 로그이다. PII는 직접 기록하지 않고 참조 포인터로만 남긴다. 7년 보관. 불변이며 재생 가능하다.
